# AI 短片创作指南

> 这是短片的领域契约。平台工具、项目当前状态和可用模型以 `recut.context`、`recut.project_context` 与 `workflow.context` 为准。

## 先读状态，再做唯一允许的事

每次创作动作前调用 `workflow.context`。它是唯一真相源：决定当前阶段、风格模板、已确认资源和 `allowedActions`。不得用聊天记忆跳过资料确认或方案选定。

```text
立项 → 资料研究 → [用户确认资料] → 创作方案 → [用户选定方案]
→ 剧本与场景方案 → 视觉设定 → 关键画面 → 声音设计 → 场景视频 → 成片交付 → 短片交接包
```

## 立项：冻结导演配置

先调用 `brief.create` 保存：选题、补充约束、画幅、时长和一个风格模板。模板是项目的导演配置，包含：

- `referenceImagePrompt`：本片视觉设定参考图的起点；
- `visualPrompt`：所有关键画面复用的视觉语言；
- `directorMethod`：故事如何推进、镜头如何承担叙事。

目前内置 Vox 编辑解说、手绘随笔、卡通角色叙事。它们都是模板，不是产品类别；AI 短片可以继续扩展模板，但不得在项目进行中悄悄替换已经冻结的风格。

在立项读到 `styleTemplate.referenceGuide` 后，必须加载对应的同级 `references/` 文件，再开始视觉设定、关键画面或 Remotion 交接。参考包规定镜头语法、材质、色彩、叙事动作与禁忌；它是生成与评审依据。`referenceImages` 只有一张供用户选择模板时显示的 `cover.png`，不可当作具体生成参考。具体的手绘、角色、材质或镜头参考须由用户在项目中生成或上传为 Recut 素材；若用户提供了有权使用的参考图，优先使用它。

## 资料研究：先把外部资料变成全局素材

资料研究不是一段搜索摘要。文章、YouTube、小红书、抖音、论文或网页都先调用 `recut.media.create_reference`，登记为全局 `reference` 素材：规范 URL、来源类型、标题、事实摘要、作者和发布时间。来源越完整越好——文章/网页必须把读到的正文全文写入 `content`，让它成为真正可审阅的文章数据；有代表性的图片把字节经 `imageData`（base64）随素材保存为真实的图片数据；YouTube 等平台无法保存正文，就补齐全套可得的元数据（频道名、频道 URL、时长、播放量、点赞、描述与语言）。平台只保存你提交的内容，不抓取或伪造原站。

然后保存 `research` 资料研究资源：`sources[]` 只保存 `assetId`、标题、类型、与短片相关的洞见和可信度/偏见判断。至少需要三条不同来源，既有支持证据也有反例或限制。保存时 `status: "draft"`，必须停下由用户判断“资料足够”。用户确认后才可调用 `research.approve`。

全局 `reference` 素材可被其他短片项目和 Remotion Studio 复用；短片项目只保存它的稳定 ID 和自己的研究判断。

## 创作方案与剧本：先选叙事，再生产画面

资料已确认后，`proposals` 给出 2–3 个不同的讲述方案。每个候选必须说明：一句话梗概、论点、叙事弧、引用的来源 `assetId` 和为什么现在值得看。保存 `selectionStatus: "pending"` 后停止；只能由用户用 `proposal.select` 选定一个。

选定后创建 `script`。`scenes[]` 是生产计划：每项约 5 秒、一个信息变化，拥有场景 ID、旁白、视觉计划、叙事目的、时长和研究 `sourceIds`。时长总和必须匹配立项配置。剧本阶段绝不生成媒体。

## 视觉设定、关键画面、声音设计与场景视频

视觉设定不是风格选择器，而是已选模板针对本片物化的一张视觉圣经图：必须覆盖人物/主体、核心道具、信息元素、空间材料和层次，并保存真实 `media.assetId`、原始提示词和导演方法。

**关键画面：五段提示词结构**

1. 固定风格块：使用立项阶段冻结的 `styleTemplate.visualPrompt`；
2. 场景行动：只描述当前剧本场景的一个信息变化；
3. 构图与层次：主体、道具、环境、负空间和安全区；
4. 连续性锚点：角色、材质、色彩、镜头世界不得漂移；
5. 技术约束：使用立项画幅，不生成可读正文、标志或水印。

图片生成必须先读取当前平台配置；使用 `recut.image.generate` 或宿主的原生图片能力。原生图片必须经 `recut.media.import_image` 归档，只有真实素材 ID 才能进入视觉设定或关键画面。

声音设计的每个场景必须拥有真实旁白素材。使用 `recut.media.list_voices → recut.speech.generate_async`，等待终态后保存。场景视频一次默认只生产一个：以对应关键画面与声音设计的素材 ID 调用 `recut.video.generate_async`；视频提示词必须逐字包含旁白并声明参考音频为唯一人声，禁止新增语言。提交成功后立刻用稳定的排队中素材 ID 创建独立场景视频资源。

不要用 HyperFrames、ffmpeg、浏览器自动化或本地渲染替代媒体生成。最终成片交付的两轨确定性导出是例外：由面板调用 `delivery.export → ctx.media.compose`。

## 短片交接包与 Remotion 交接

完成后调用 `film.package` 发布 `recut.ai-short-film.package@1` 交接产物。它包含：立项、资料研究、选定方案、剧本与场景方案、冻结风格/视觉设定，以及关键画面、声音设计、场景视频和成片交付的稳定素材 ID。

Remotion Studio 应消费这个交接包：复用已确认的叙事、场景时序、导演约束和素材 ID；它负责代码化排版、动态图层、字幕和可控合成，不应重写已经确认的创作决定或读取短片应用的私有数据库。

## 不可违反的规则

1. 只有用户确认资料研究后才可提出创作方案；只有用户选定创作方案后才可写剧本。
2. 每次只产生当前阶段的交付物；媒体失败时如实报告，不能用文字假装素材已生成。
3. section 不保存彼此的资源 ID 或依赖图；需要前序信息时先读取 `workflow.context.inputs`，由 Agent 判断素材、证据和叙事如何关联。局部修复先 `resource.read`，再用 `resource.update.itemPatch` 精确更新。
4. 一镜只服务一个信息变化。时长变长时增加场景，不拉长单张关键画面或单段视频。
5. 用户在创作要求中用 `@` 添加的当前项目条目或系统素材是本次任务的临时上下文。可读取和使用它们，但不得将其保存为 section 依赖或改变线性阶段。
